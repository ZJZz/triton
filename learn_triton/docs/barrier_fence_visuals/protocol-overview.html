sm80 / sm86
cp.async

一条典型的“先把 global tile 异步搬到 shared，再把 shared tile 发布给整个 CTA”协议。

source .global / HBM tile

payload 一开始在 global memory。consumer 读的不是这里，而是后面的 shared stage。

engine cp.async pipe

真正搬 bytes 的是异步 copy pipe，不是 consumer warp 自己同步 load。

destination .shared::cta stage buffer

tile 先落到 CTA shared，供后续 local_load / mma.sync 消费。

wait object thread-local async group completion

`wait_group` 先由 issuing thread 观察自己发出的 group 是否完成。

scope thread -> CTA

先 thread wait，再用 `bar.sync` / `ttg.barrier` 把 tile 发布到整个 CTA。

consumer same CTA readers

最终能合法读的是同一 CTA 的其他 warps，而不是只有 issuing warp。

sm90
TMA + mbarrier

一条“descriptor 驱动大块搬运，再用 mbarrier phase 做共享完成模型”的 transport protocol。

source .global / HBM tile

payload 仍来自 HBM，但还需要一份 TensorMap 描述符告诉 TMA 怎么解释它。

engine TMA engine

大块或张量拷贝由 TMA 执行，leader thread 只是发起者，不是数据搬运者。

destination .shared::cta / ::cluster

tile 的落点和 mbarrier 的落点放在哪里，就决定 reader scope 扩到哪里。

wait object mbarrier phase / expected bytes

`wait_barrier` 真正观察的是 completion object 的 phase，不是 engine 本身。

scope CTA or cluster

当 mbarrier 和目标缓冲在 CTA shared 时就是 CTA 模型；在 cluster shared 时就扩到 cluster。

consumer CTA / cluster readers

reader 与 mbarrier 共享同一作用域时，才会在 wait 返回后获得合法读取权。

sm90
WGMMA

一条“shared tile 已经就位，先做 proxy publish，再等 warp-group async compute 完成”的 compute protocol。

source .shared::cta tile

这里不从 HBM 开始。输入 tile 已经在 shared，通常由更早一步 producer warps 写好。

engine wgmma.mma_async set

多个 async MMA 先发出并 commit 成组，真正的核心是 warp-group compute pipeline。

destination accumulator registers

结果先落在寄存器累加器里，而不是回到 shared 或 HBM。

wait object committed async MMA groups

这里有两层同步：`fence.proxy.async` 解决可见性，`wait_group` 才解决 completion。

scope warp-group

`wait_group` 不是 CTA barrier。它只释放同一个 issuing warp-group。

consumer same warp-group next stage

通常还是同一个 WG 接着复用 accumulators，进入下一阶段。

sm100
tcgen05 / TMEM

一条“shared tile 喂给 tcgen05，结果写 TMEM，再分两段证明完成与 legality”的 Blackwell protocol。

source .shared::cta / ::cluster tile

这一页通常从 shared operand 开始看，前置搬运阶段视为已经完成。

engine tcgen05 set

多个 `tc_gen5_mma` 先扇出到 async tensor core 5 路径，再由 commit / wait 汇合。

destination TMEM

结果主体写在 tensor memory 里，这是与 WGMMA / shared protocol 最容易混淆的地方。

wait object mbarrier completion + optional hazard barrier

`wait_barrier` 先证明 async compute 完成；若有 TMEM reuse hazard，还要再过一道 barrier。

scope partition-specific, then CTA-group legality

launch scope 取决于 compute partition；hazard repair 则取决于哪些 reader 会共享 TMEM reuse 风险。

consumer next legal TMEM reader

下一位 reader 只有在 completion 和 legality 两层都满足后才真正可以读。
